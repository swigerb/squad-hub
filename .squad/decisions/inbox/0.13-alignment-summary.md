|---|---|

| `costPolicy` is a mode string with categories and fallback chains | It is an **object**: `{ maxCategory?: 'lightweight' \| 'versatile' \| 'powerful' }`, accepted flat or nested under `models`. No `mode`, no `categories`, no `fallbackChains`, no `"economy"` value. |

#### #156 — Resolve Squad state where Squad actually keeps it (`facf8ba`)

`src/squad-context.js` now resolves the effective state dir like upstream `effectiveSquadDir()` /
`resolveExternalStateDir()`: `teamRoot` when not `"."`, `stateLocation: "external"` + `projectKey`
into the platform global squad dir. `config.json` always reads local (it steers resolution).
`projectKey` containing `..` is refused. Never throws — falls back to `<cwd>/.squad`.

**Security took three rounds and changed the design.** Security blocked twice; the dispute went to
`advisor`, who ruled: resolve like upstream, but if the effective root canonicalizes **outside the
project root**, do not read it unless the operator opts in via `followExternalSquadState` in
squad-hub's *own* config (default `false`, excluded from `publicView()`, not settable by the observed
repo). Hard containment was rejected because `squad link` is real and absolute `teamRoot`s are normal.

The bug worth remembering: gating only the remote/external branches left a hole. Git can check out a
symlink, so a cloned repo can ship `.squad` as a link elsewhere, take the plain *local* branch, and
bypass the gate entirely. Local roots and local documents are now canonicalized and confined too, on
**every** entry point — a gate on one is no gate at all. Containment uses `path.relative()` +
not-absolute + not-starting-`..`, never `startsWith` (`C:\a\b` vs `C:\a\bc`).

**Accepted residual risk:** with the flag on, squad-hub may relay allowlisted Squad docs from that
trusted external root. That is the point of the flag, and it is documented in `docs/security.md`.

#### #158 + #159 — Prefer Squad's own capabilities block (`8c40f3f`)

Parses the generated block from `.github/agents/squad.agent.md` (markers, headers and `; `-separated
boundary lists matched byte-for-byte against v0.13.1, including the em-dash empty cell and both
empty-boundary placeholders). Prefers it for roster and routing hints; falls back to `team.md` when
missing, pending or malformed. `memberSource` records which path produced the roster. `costPolicy`
and `economyMode` surface next to the model summary in the session view and API shape; an
unrecognised `maxCategory` is ignored rather than echoed. Existing `defaultModel` /
`agentModelOverrides` behaviour unchanged. All new DOM values escaped and covered in the XSS suite.

#### #157 — Ask Squad how healthy it is (`95ada30`, anchor repair `9ec66bb`)

`squad-hub doctor` runs `squad health --json` when the cwd is a Squad project and `squad` >= 0.13 is
on PATH, rendering pass/fail per check and naming the **specific** reason when unavailable (not a
Squad project / not on PATH / version too old, naming the version found / timed out / unparsable /
crashed). Exit code 1 with a valid report is a result, not an outage. `skip` is not a failure.

Session view carries a summary only, computed on-device, cached per cwd with TTL and an LRU cap of
128. Session start never awaits the subprocess. Only `{status, checks:[{id,status}]}` crosses to the
hub — diagnostics, messages and stderr can carry local paths and usernames and stay on-device.

**This took four review rounds.** The subprocess surface is where the real work was:
1. `taskkill` was invoked by bare name; Windows can resolve an executable from the working directory,
   so an observed repo shipping `taskkill.exe` would have had it run on every timeout. Now absolute
   from System32.
2. npm installs `squad` as a `.cmd` shim, which `spawn()` cannot exec directly — the honest fix is
   `cmd.exe`, which is the thing we were avoiding. Invoked absolute with `/d` (no AutoRun) and
   `/v:off` (no delayed expansion); only `.cmd`/`.bat` take that route.
3. Reviewer then **proved the shim path itself was still parsed as cmd syntax** — a PATH directory
   named `x & copy NUL injected.txt & rem` created the file. Now quoted with
   `windowsVerbatimArguments`; anything unprovable (quotes, pipes, `%` expansion, control chars,
   backslash-before-quote) **fails closed** with an honest unavailable reason. A regression runs that
   exact attack and asserts no side effect.

#### Pre-existing failures fixed (`ae9b0c1`, `9ec66bb`)

Four tests were failing on this branch's base, unrelated to the four issues:
- Three asserted `retro-action` against `.github/workflows/sync-squad-labels.yml`. The label was live
  on GitHub but defined in no group, so the workflow would have dropped it on the next rebuild. Added
  a `CEREMONY_LABELS` group; colour and description read back with `gh label list` rather than
  invented, so the next sync is a no-op. **No test was weakened** — the gap was real.
- One was the mutation-anchor meta-test. Two causes: the `retro-action` anchor above, and #157

  to. That mutation had stopped matching — applying nothing and passing silently, leaving "the daemon
  kills its children on shutdown" proven by nothing. Re-anchored; probe now reports *caught*, not
  merely applied.
